# v1.0.0-beta.5

## 中文

本次 Beta 预发布在 beta.3 基础上增加管理员监控中心，重点完善故障诊断、探测成本控制和日常运维。用于功能评估、升级验证与反馈，不是 RC 或正式稳定版。

beta.4 的发布门禁因集成测试登录超时失败，未生成 Release 或安装包；本版修复测试后使用新标签发布，保留原标签用于追溯。

### 新增

- **监控中心**：管理后台新增统一入口，包含诊断、模型变更、备份、告警规则、事件、调度和费用。
- **故障诊断**：记录 DNS、连接、TLS、首字节、首段有效文本和完整响应耗时，并提供受限的 HTTP 状态、请求 ID 与 Retry-After。公开状态接口不暴露诊断元数据。
- **模型清单变更**：成功的自动发现建立清单基线，后续新增模型经管理员批准后参加探测；发现失败不会被误认作模型批量下线。
- **一致性备份**：支持手动与定期 SQLite 快照、保留数量、SHA-256 和数据库结构校验。备份默认保存在数据目录的 `backups/` 中。
- **独立告警规则**：按 Provider / 模型配置独立渠道、阈值与冷却；支持规则测试及保持原路由的通知重试。同一范围可配置多条规则，发送到不同渠道。
- **运维提醒**：可订阅模型清单变更、备份失败和月度预算越限；发送前持久预留，限制自动重试，避免中断后盲目重复发送。
- **事件中心**：记录模型及模型发现异常、人工接手和备注、恢复时间；未知结果不会作为恢复证据，连接版本变更与真实恢复分开处理。
- **Provider 调度**：独立检测周期、慢响应阈值和规则维护窗口；下次执行时间持久保存，仍遵守单实例任务互斥与请求预算。
- **能力检测**：可选文本包含、JSON 对象及顶层字段断言，以及非流式 Chat 工具调用结构、Embedding 向量探测。工具检测不会执行外部动作。
- **费用估算**：按 Provider / 模型设置输入与输出 USD 单价；按结果入库时价格保存估算金额，未知费用单列，历史金额不随改价重算。

### 修复与保护

- 集成测试的登录准备阶段使用独立超时，兼容共享 CI 运行器上的 race 插桩开销；任务接口仍保留 2 秒响应时限。未降低密码校验强度或修改生产接口超时。
- 清单比较不会改变上游返回的探测顺序，避免模型数量上限下的检测范围漂移；批准新增模型不会遗忘暂时消失的已批准模型。
- 配置保存成功、后续刷新失败时仍保留服务器确认的版本，允许继续刷新；支持放弃本地更改后重新加载。
- 旧连接版本的清单事件不向新连接发送提醒；通知重试不会从原规则回退到全局渠道。
- 用量缺失、字段不完整或负数不会被当成已知零费用。
- 监控管理接口沿用管理员会话、同源和 CSRF；通知凭据不由读取接口返回。备份操作限制文件名、路径和文件类型。
- 发布工作流新增监控中心桌面/移动浏览器回归，覆盖配置、凭据隐藏、批准、事件接手、备份校验及刷新失败恢复。

### 升级注意

1. 升级前停服，备份完整数据目录、旧程序和服务配置。启动会创建新增表和列；回退应恢复匹配的程序与数据库备份。
2. 下载对应平台的完整压缩包并核对 `SHA256SUMS.txt`，保留 `web/`、文档和资源。保留原数据库路径和进程环境变量。
3. 新告警规则、定期备份和独立调度默认不启用。旧全局设置与通知保留；开启独立调度后，应配置 Provider 范围告警。全局告警仍以完整全量检测为依据。
4. 第一次成功发现建立基线；连接版本变更会建立新基线。后续新增模型在监控中心批准，不立即触发检测，仍受模型排除、数量上限和请求预算约束。
5. 原配置 JSON 导入/导出不包含新监控配置；完整迁移须使用数据库备份。备份包含账号、会话、API Key 与通知凭据，需要严格限制访问。
6. Beta 更新请选择 `preview` 通道，或指定 `--version v1.0.0-beta.5`。Docker 在宿主机更新镜像并保留数据卷。

### 验证与限制

- 发布门禁包含 Linux Go race、Windows Go 测试、`go vet`、前后端漏洞扫描、前端单元测试与构建、浏览器回归和隔离安装脚本测试。
- Windows 隔离升级检查覆盖旧版账号与会话保留、新增监控表初始化及备份创建和校验；不替代真实部署环境的升级验收。
- 独立调度每分钟检查到期项，可能因长任务、预算不足或任务互斥延迟，不保证整点执行。原全局通知不以局部模型重测作为恢复证据。
- 费用只估算已知用量，不覆盖未知消耗或供应商特殊计价；不是账单，也不是强制费用上限。探测会真实消耗 Token。
- 在线备份会占用磁盘空间并可能延迟数据库操作。结构与哈希校验不能替代恢复演练；本版没有网页覆盖恢复入口。
- 真实上游兼容性、长期调度、磁盘耗尽及跨平台恢复仍需目标环境验收。真实 Linux/systemd 更新、失败回滚及断电恢复尚未完成实机验收。
- HTTPS 与 SHA-256 不是独立发布签名；不支持原生 Anthropic/Gemini、图像或音频探测。
- 本版为预发布，不更新稳定版或 Docker `latest` 标签。已有版本标签与附件保持不变。

## English

This Beta prerelease adds an administrator monitoring center on top of beta.3, focusing on diagnostics, probe cost control and routine operations. It is intended for evaluation, upgrade validation and feedback, not as an RC or stable production release.

The beta.4 release gate failed because an integration-test login timed out, so it has no Release or downloadable packages. This version fixes the test and uses a new tag, preserving the earlier tag for traceability.

### Added

- **Monitoring center**: a new admin entry for diagnostics, model changes, backups, alert rules, incidents, scheduling and estimated costs.
- **Probe diagnostics**: DNS, connection, TLS, first-byte, first-text and full-response timing, with limited HTTP status, request ID and Retry-After metadata. Public status endpoints do not expose diagnostic metadata.
- **Model catalog changes**: successful discovery establishes a baseline; subsequent new models require administrator approval before probing. Failed discovery is not treated as mass model removal.
- **Consistent backups**: manual and scheduled SQLite snapshots, retention limits, SHA-256 and database integrity checks. Backups are stored under `backups/` in the data directory.
- **Independent alert rules**: separate destinations, thresholds and cooldowns scoped to providers/models, with rule tests and route-preserving retries. Multiple rules can send the same scope to different channels.
- **Operational notices**: optional notifications for catalog changes, backup failures and monthly budget thresholds, with persistent delivery reservations and bounded automatic retries.
- **Incident center**: model and discovery incidents, acknowledgement, notes and observed recovery times. Unknown results do not prove recovery; connection-generation changes are distinguished from actual recovery.
- **Provider scheduling**: separate intervals, slow-response thresholds and rule maintenance windows, with persisted next-run times while retaining single-task execution and request budgets.
- **Capability checks**: optional text containment, JSON-object and top-level-key assertions, non-streaming Chat tool-call structure checks and embedding-vector probes. Tool checks never execute external actions.
- **Cost estimates**: configurable USD input/output prices per provider/model. Estimates use prices effective when results are stored; unknown costs are tracked separately and price changes do not rewrite historical amounts.

### Fixes And Safeguards

- Integration-test login setup has its own timeout to accommodate race instrumentation on shared CI runners. Task requests retain their two-second deadline. Password verification strength and production API timeouts are unchanged.
- Catalog comparisons preserve upstream discovery order so model-count limits do not silently change the monitored set. Approving new models retains approval for temporarily missing models.
- A confirmed configuration save retains its server version even when the following refresh fails. Local edits can be discarded before reloading.
- Catalog events from old connection generations are not sent for new connections. Retrying a rule notification never falls back to the global destination.
- Missing, incomplete or negative usage fields are not interpreted as known zero cost.
- Monitoring endpoints require administrator sessions, same-origin requests and CSRF protection. Read endpoints omit notification credentials. Backup operations restrict names, paths and file types.
- The release workflow now includes desktop/mobile monitoring-center regressions for settings, credential redaction, approvals, incident acknowledgement, backup verification and refresh-failure recovery.

### Upgrade Notes

1. Stop the service and back up the complete data directory, previous program and service configuration. Startup creates additional tables and columns; rollback requires matching program and database backups.
2. Download the full archive for your platform, verify `SHA256SUMS.txt`, and retain `web/`, documentation and assets. Preserve database paths and process environment variables.
3. New rules, scheduled backups and independent scheduling are disabled by default. Existing global settings and notifications remain. Configure provider-scoped alerts when enabling independent scheduling; global alerts still require complete full checks.
4. The first successful discovery establishes a baseline, and a new connection generation establishes a new baseline. Approving later additions does not start a check immediately; exclusions, model limits and request budgets still apply.
5. Existing configuration JSON import/export does not include the new monitoring settings. Use database backups for complete migration. Backups contain accounts, sessions, API keys and notification credentials and require restricted access.
6. Select the `preview` update channel for Beta releases, or specify `--version v1.0.0-beta.5`. Update Docker images on the host while preserving data volumes.

### Validation And Limits

- Release gates include Linux Go race tests, Windows Go tests, `go vet`, backend/frontend vulnerability scans, frontend unit tests/build, browser regressions and isolated installer tests.
- An isolated Windows upgrade check covers preserved accounts and sessions, new monitoring tables, and backup creation/verification. This does not replace acceptance testing in real deployments.
- Independent scheduling checks due work once per minute. Long tasks, exhausted budgets or task contention may delay execution; exact wall-clock execution is not guaranteed. Partial model retries are not recovery evidence for global notifications.
- Costs estimate known usage only, excluding unknown consumption and special supplier pricing. They are neither invoices nor hard spending caps. Probes consume real upstream tokens.
- Online backups consume disk space and may delay database operations. Integrity and hash checks do not replace restore drills; this version has no web-based overwrite/restore endpoint.
- Real upstream compatibility, sustained scheduling, disk exhaustion and cross-platform restores still require target-environment acceptance testing. Real Linux/systemd updates, failed-update rollback and power-loss recovery have not completed acceptance testing.
- HTTPS and SHA-256 do not provide independent release signatures. Native Anthropic/Gemini, image and audio probes are not supported.
- This is a prerelease and does not update the stable release or Docker `latest` tag. Existing version tags and assets remain unchanged.
