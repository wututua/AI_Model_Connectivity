# v1.0.0-beta.2

## 中文

这是修复已知问题的第二个预发布版本，供评估和升级验证使用，不是正式稳定版。包含 beta.1 的七项已知问题修复，以及发布前发现的构建依赖安全更新；不修改 beta.1 的标签或下载文件。

### 修复

1. 保存 Provider 时自动合并尚未添加的手动模型输入；保存失败后保留选择，显式清空才恢复自动发现。
2. Provider/模型身份键对 Provider ID 编码，避免 `::`、尾随冒号和百分号造成冲突。探测、报告及历史读取使用一致的键，SQLite 历史按独立的 Provider、模型列查询和裁剪。
3. HTTP 错误和错误信封保留上游明确返回的 token 用量，继续计入报告和用量统计；关闭历史记录也不影响用量入库。
4. 没有模型结果的未检测 Provider，以及空范围或全暂停范围，不再触发恢复通知，也不消耗原有通知状态或冷却时间。
5. 按模型限定的告警排除无关 Provider 的发现失败，同时保留范围内已知模型或明确指定 Provider 的发现失败。
6. 运行概览按请求顺序保护任务摘要与运行状态，忽略旧刷新响应及其错误，不再覆盖已完成任务的结果。
7. 移除文件式环境配置及重载入口，统一文档：环境变量用于启动和首次初始化；SQLite 中已保存的运行时设置优先，通过设置界面/API 修改后立即生效。状态页登录保护覆盖 REST 与 SSE。
8. 将间接构建依赖 `source-map-js` 升级至 `1.2.2`，处理发布前依赖扫描发现的高危拒绝服务漏洞。

### 升级注意

- 升级前备份 SQLite；启动参数使用进程环境变量，尤其保留原有数据目录、数据库路径和安全 Cookie 设置。
- 升级后执行一次完整检测，以重建旧快照中的历史统计并确认当前连接状态。
- 旧 SQLite 历史可按独立身份字段读取；此前已漏测或裁剪的数据、未保存的用量无法还原。只有有歧义拼接键的旧 JSON 也无法可靠拆分。
- 用量统计仅汇总上游实际返回的数据，不能替代上游账单。

### 验证与限制

- 本地通过 Go 全量测试、`go vet`、36 项前端单元测试、生产构建、桌面/手机浏览器回归及身份键模糊测试。
- 发布工作流要求 Linux race、Windows Go 测试、前后端漏洞扫描及浏览器回归通过后，才生成六个平台压缩包并创建 GitHub Release。
- 交叉编译不等于原生运行验证；容器启动、持久卷及原生 macOS/ARM 运行行为仍需在目标环境确认。
- 检测会真实调用上游接口并消耗 token；用量统计和通知不能替代上游账单或独立健康检查。

### 下载与启动

- 下载对应平台压缩包，校验 `SHA256SUMS.txt` 后完整解压。
- 在解压目录运行 `model-connectivity`，Windows 使用 `model-connectivity.exe`；用 `--version` 确认版本与提交信息。
- 包内自带 `web/`、文档和资源，无需本地编译前端。初次登录后完成密码修改，通过管理面板维护日常设置和 Provider。
- 此版本标记为预发布，不更新正式版本或 Docker 的 `latest` 标签。

## English

This second prerelease is for evaluation and upgrade validation, not a stable production release. It fixes the seven known beta.1 issues and includes a build-dependency security update found during release checks. The beta.1 tag and downloads remain unchanged.

### Fixes

1. Saving a provider includes pending manual model input. Failed saves retain the selection for retry; only explicit clearing restores automatic discovery.
2. Provider/model keys encode provider IDs to avoid collisions involving `::`, trailing colons and percent signs. Probes, reports and history share the same keys; SQLite queries and prunes by separate provider and model columns.
3. HTTP errors and error envelopes retain explicitly reported token usage in reports and billing aggregates, including when history recording is disabled.
4. Unchecked providers without model results, empty scopes and fully paused scopes no longer trigger recovery or consume notification state or cooldown.
5. Model-scoped alerts exclude unrelated discovery failures while retaining failures for matching known models or explicitly selected providers.
6. Overview request ordering protects completed task summaries and running state from older refresh responses and stale errors.
7. File-based environment configuration and reload entry points are removed. Documentation now consistently states that environment variables initialize startup settings, persisted SQLite runtime settings take precedence, and UI/API runtime changes apply immediately. Status login protection covers REST and SSE.
8. The transitive build dependency `source-map-js` is updated to `1.2.2` to address the high-severity denial-of-service vulnerability found by the prerelease dependency audit.

### Upgrade Notes

- Back up SQLite first. Set startup parameters through the process environment and preserve existing data paths, database paths and secure-cookie settings.
- Run a full check after upgrading to rebuild historical statistics in cached snapshots and verify current connections.
- Existing SQLite history remains readable through separate identity columns. Previously skipped probes, pruned samples and unrecorded usage cannot be recovered. Ambiguous keys in legacy JSON cannot be reliably split either.
- Usage statistics only aggregate data actually returned by upstream services and are not a substitute for upstream billing.

### Validation And Limits

- Local checks passed: the full Go suite, `go vet`, 36 frontend unit tests, production build, desktop/mobile browser regressions and identity-key fuzz testing.
- The release workflow requires Linux race tests, Windows Go tests, backend/frontend vulnerability scans and browser regressions before producing six platform archives and creating the GitHub Release.
- Cross-compilation is not native runtime validation. Container startup, persistent volumes and native macOS/ARM behavior still require validation in the target environment.
- Checks make real upstream requests and consume tokens. Usage statistics and notifications do not replace upstream billing or independent health checks.

### Downloads And Startup

- Download the archive for your platform, verify it against `SHA256SUMS.txt`, and extract it completely.
- Run `model-connectivity`, or `model-connectivity.exe` on Windows, from the extracted directory. Use `--version` to verify the version and commit.
- Archives include the prebuilt `web/` directory, documentation and assets. Complete the initial password change, then manage providers and everyday settings through the admin panel.
- This release is marked as a prerelease and does not update the stable release or Docker `latest` tag.
