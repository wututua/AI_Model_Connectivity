# v1.0.0-beta.3

## 中文

第三个 Beta 预发布版本，面向功能评估、升级验证和问题反馈，不是 RC 或正式稳定版。本次在 beta.2 基础上增加检测、通知、运维与部署能力，并修复系统更新的并发和断线恢复问题。已有标签和发布附件保持不变。

### 新增

- Provider 分组、标签、批量启停与暂停，以及不含 API Key 的配置复制。
- 单模型、多模型及失败项重测，保留未重测模型的结果和时间，并展示检测阶段进度。
- Provider 级提示词、输出上限、temperature、超时和兼容预设；支持 Chat Completions、Responses 及流式首段文本延迟。
- 通知连续异常/恢复阈值、维护窗口、测试、发送历史与手动重试；重启中断的发送标记为结果未知。
- UTC 每日请求预算、自动发现确认阈值、历史/用量 CSV 导出和脱敏诊断。
- 可创建、轮换、撤销的 Prometheus 指标专用凭据，仅允许读取指标，数据库只保存凭据哈希。
- 独立 Linux/systemd 安装脚本，启动时选择简体中文或 English，可交互设置监听 IP 和端口；支持备份、升级、失败恢复和保留数据的卸载。
- 管理后台检查稳定版与预发布版本，显示纯文本发布说明及更新任务进度。脚本管理的 Linux 安装可主动启用独立更新服务，由管理员确认后执行完整发布包升级。

### 修复与安全

- 更新任务从待处理交接为运行中时重新核对状态，避免误判空闲并放行重复更新或检测。
- 提交更新增加超时，期间继续轮询任务状态。一次性提交凭据和结果确认接口允许安全处理断线及服务器错误，不自动重复安装；延迟到达的旧请求不能再次排队。
- 修复批量接口与特殊 Provider ID 的路由冲突、模型选择范围不一致、已删除 Provider 的残留选择及旧刷新响应覆盖新操作结果的问题。
- 配置、模型和告警范围变更后隔离旧检测结果，重新累计相关通知证据；停用通知时清除候选计数。
- 将 `golang.org/x/mod` 升级至 `v0.40.0`，处理依赖模块的两条安全公告；此前扫描未发现应用调用受影响路径。
- 更新接口保持管理员会话、同源与 CSRF 校验。应用仍以非 root 账户运行，特权更新执行器只处理固定官方仓库的发布版本。

### 升级注意

1. 停止服务并备份整个数据目录、旧程序和服务配置。新版本会初始化新增表和字段；回退时应恢复配套的程序与数据库备份，不要只替换二进制。
2. 下载对应平台完整压缩包，核对 `SHA256SUMS.txt`，保留包内 `web/`、文档和资源；启动时保留原数据库路径及进程环境变量。
3. 已保存的 Provider 和运行设置仍以 SQLite 为准。升级后检查检测预算、模型范围、通知及状态页登录要求，再执行一次完整检测。
4. 手动部署和旧版部署不会被安装脚本自动接管。仅脚本管理的安装使用脚本升级；其他部署按部署文档手动升级，Docker 在宿主机更新镜像并重建容器，保留数据卷。
5. Beta 通道须显式选择 `preview`，也可指定 `--version v1.0.0-beta.3`。默认监听 `127.0.0.1:8080`；公网访问需要自行配置防火墙和 HTTPS。

### 可选系统更新

先安装本版本，再由服务器管理员审核脚本并执行：

```bash
sudo bash install-model-connectivity.sh enable-updates
```

- 默认不启用后台安装，不会自动安装或定时重启。启用操作会短暂停服、备份并恢复原运行状态。
- 更新服务先下载与校验完整发布包，再停服备份；新服务健康检查失败时尝试恢复旧程序、数据库和服务。
- 特权执行器和安装器副本不会随应用升级自动替换；刷新它们需要服务器管理员再次执行 `enable-updates`。
- `pending`、`running` 长时间不变或出现 `recovery_required` 时，检查 systemd 日志及备份，不要删除状态或强行重复更新。

### 验证与限制

- 本地回归覆盖 Go 全量测试、`go vet`、前端单元测试和构建、桌面/移动浏览器交互、隔离安装脚本及更新任务并发与异常恢复。
- 发布工作流要求 Linux race、Windows Go 测试、前后端漏洞扫描、浏览器回归和安装脚本测试通过，再构建六个平台发布包。
- **真实 Linux/systemd 启用、升级、失败回滚和断电后的人工恢复尚未完成实机验收。请在隔离测试环境评估可选更新功能，不要用于无人值守的关键生产升级。**
- 突然断电、进程强制终止、磁盘耗尽或 systemd 故障不保证自动恢复。HTTPS 与 SHA-256 校验不等于独立发布签名验证。
- 交叉编译不等于原生运行验证；容器持久卷及原生 macOS/ARM 行为仍需在目标环境确认。
- 检测会真实消耗上游 token。用量统计、请求预算和通知不能替代上游账单或独立健康检查。
- 本版本标记为预发布，不更新正式版或 Docker `latest` 标签。

## English

The third Beta prerelease is intended for feature evaluation, upgrade validation and feedback, not as an RC or stable production release. It adds monitoring, notification, operations and deployment capabilities on top of beta.2, and fixes update concurrency and connection-loss recovery. Existing tags and release assets remain unchanged.

### Added

- Provider groups, tags, batch enable/disable and pause controls, plus configuration copying without API keys.
- Checks for individual models, selected models or failed models, preserving untouched results and timestamps while showing detection progress.
- Per-provider prompts, output limits, temperature, timeouts and compatibility presets; Chat Completions, Responses and streaming first-text latency.
- Consecutive failure/recovery thresholds, maintenance windows, notification tests, delivery history and manual retries. Deliveries interrupted by a restart are marked as uncertain.
- UTC daily request budgets, discovery confirmation thresholds, history/usage CSV exports and redacted diagnostics.
- Dedicated Prometheus credentials with creation, rotation and revocation. They only authorize metrics reads, and only credential hashes are stored.
- A standalone Linux/systemd installer with an interactive Simplified Chinese or English selector and configurable listen address/port, plus backups, upgrades, failure recovery and data-preserving uninstall.
- An admin update page with stable/prerelease checks, plain-text release notes and task progress. Installer-managed Linux deployments can explicitly enable a separate updater for administrator-confirmed full-package upgrades.

### Fixes And Security

- Recheck state during the pending-to-running handoff so updates are not briefly treated as idle, allowing duplicate updates or model checks.
- Bound update submissions with a timeout while continuing status polling. Single-use submission credentials and a resolution endpoint handle lost responses and server errors without automatically reinstalling; delayed old requests cannot enqueue again.
- Fix batch routing conflicts with special provider IDs, inconsistent model-selection scopes, retained selections for deleted providers and stale refresh responses overwriting newer changes.
- Isolate outdated detection results after configuration, model or alert-scope changes and reset relevant notification evidence. Disabling notifications clears pending evidence counts.
- Update `golang.org/x/mod` to `v0.40.0` to address two module-level security advisories. Earlier scans found no application calls to the affected paths.
- Update endpoints retain admin-session, same-origin and CSRF checks. The application remains non-root, and the privileged worker only handles releases from the fixed official repository.

### Upgrade Notes

1. Stop the service and back up the complete data directory, old program and service configuration. This version initializes additional tables and columns; restore matching program and database backups when rolling back, not just the executable.
2. Download the complete archive for your platform, verify `SHA256SUMS.txt`, and retain its `web/` directory, documentation and assets. Preserve existing database paths and process environment variables.
3. Persisted provider and runtime settings remain authoritative in SQLite. Review budgets, model scopes, notifications and status-page login requirements before running a full check.
4. The installer does not automatically adopt manual or older unmanaged deployments. Use script upgrades only for script-managed installs; otherwise follow the manual deployment guide. Update Docker images and recreate containers on the host while preserving data volumes.
5. Explicitly select `preview` for Beta releases, or use `--version v1.0.0-beta.3`. The default listen address is `127.0.0.1:8080`; configure firewalls and HTTPS yourself before exposing it.

### Optional System Updates

Install this version first, then have the server administrator review the script and run:

```bash
sudo bash install-model-connectivity.sh enable-updates
```

- Web installation is disabled by default, with no automatic installation or scheduled restart. Enabling it briefly stops the service, backs it up and restores its previous running state.
- The updater downloads and verifies a full release before stopping the application for an offline backup. Failed startup health checks trigger an attempt to restore the old program, database and service.
- Privileged worker and installer copies are not automatically replaced by application upgrades. A server administrator must run `enable-updates` again to refresh them.
- Inspect systemd logs and backups when `pending` or `running` persists, or when a task enters `recovery_required`. Do not delete state or force a duplicate update.

### Validation And Limits

- Local regression coverage includes the full Go suite, `go vet`, frontend unit tests and build, desktop/mobile browser workflows, isolated installer tests, and concurrent/error-path update tests.
- The release workflow requires Linux race tests, Windows Go tests, backend/frontend vulnerability scans, browser regressions and installer tests before building six platform archives.
- **Real Linux/systemd enablement, upgrades, failed-update rollback and manual recovery after power loss have not completed acceptance testing. Evaluate optional updates in an isolated environment, not for unattended upgrades of critical production services.**
- Power loss, forced termination, disk exhaustion or systemd failures do not guarantee automatic recovery. HTTPS and SHA-256 checks do not provide independent release signature verification.
- Cross-compilation is not native runtime validation. Container volumes and native macOS/ARM behavior still need confirmation in their target environments.
- Checks consume real upstream tokens. Usage statistics, request budgets and notifications do not replace upstream billing or independent health checks.
- This version is marked as a prerelease and does not update the stable release or Docker `latest` tag.
