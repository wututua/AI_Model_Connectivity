# v1.0.0-beta.1

This is a prerelease for evaluation, not a production-ready stable release.
Six P2 correctness issues and one P3 documentation mismatch remain known.
Back up existing data before upgrading and review the limitations below.

## Changes

- Background detection tasks survive HTTP disconnects and expose their progress.
- Completed probe usage survives cancellation without replacing a partial report.
- Provider creation rejects duplicate IDs; endpoint changes require explicit
  confirmation of credential reuse by entering a key or clearing it.
- Persisted connection revisions prevent old checks from restoring stale status
  after endpoint, key, enabled-state, or delete/recreate changes.
- Dashboard refresh/SSE ordering and theme behavior with blocked browser storage
  have regression coverage.
- Notification platform receipts, administrator recovery, version information,
  frontend dependency updates, and compressed original font assets are included.
- Release gates cover Go tests, Linux race checks, frontend tests and browser
  regressions, vulnerability scans, and six platform builds.

## Known Issues

1. **P2: Pending manual model input can be lost on Save Provider.**
   Press Enter or click the add button and verify the selected model list before
   saving. An empty list enables automatic discovery and can expand token use.
2. **P2: Provider/model identity collisions can skip probes and mix history.**
   A provider ID containing `::` can collide with another provider/model pair.
   Avoid `::` in provider IDs.
3. **P2: Error envelopes can discard explicitly reported token usage.**
   Usage statistics can undercount failed completions. Use upstream billing as
   the source of truth.
4. **P2: An unknown provider with no model results can trigger premature recovery.**
   After changing a provider endpoint, run a full check and independently verify
   recovery instead of relying exclusively on notifications.
5. **P2: Model-scoped alerts can include unrelated model-discovery failures.**
   Set the provider notification filter as well as the model filter when a
   provider-specific scope is required.
6. **P2: An older Overview refresh can overwrite a newer completed task summary.**
   Refresh again after the task and outstanding requests finish, or consult the
   status dashboard.
7. **P3: Runtime-setting hot reload differs from the configuration guide.**
   Persisted SQLite runtime settings override newly loaded environment values.
   Change these settings through the settings UI/API, not `.env` hot reload.
   In particular, verify the effective status-login requirement before exposing
   the service.

## Validation And Limits

Local checks passed: the existing Go suite, vet and module verification;
36 frontend unit tests; TypeScript and production build; browser regressions;
Windows/Linux/macOS amd64 and arm64 cross-compilation; and the recorded npm/Go
vulnerability scans.

The supplemental audit reproductions still fail on the known issues above.
Passing existing tests does not mean those issues are fixed.

Local race testing could not run because gcc was unavailable. The prerelease
is gated on the remote branch CI, which includes Linux race tests.
Native macOS/ARM runtime behavior and container startup/persistent-volume
behavior have not been validated locally. Cross-compilation and a successful
image build are not substitutes for those runtime checks.

## Downloads And Startup

- Download the archive matching your OS and architecture.
- Extract the complete archive and run `model-connectivity` on Linux/macOS or
  `model-connectivity.exe` on Windows from the extracted directory.
- Archives include `.env.example`, `README.md`, `LICENSE`, `docs/`, `assets/`,
  and the prebuilt `web/` directory.
- Use `--version` to inspect the version and commit, and `SHA256SUMS.txt` to
  verify the archive.
- First-start administrator credentials are initialized by the service;
  protect terminal output and complete the required initial password change.
- Detection makes real upstream model requests and consumes tokens. Verify
  the model scope and scheduling settings before running checks.
- Prerelease tags must not replace the stable GitHub latest release or the
  Docker `latest` tag.
