# 操作审计

[文档索引](README.md) · [安全边界](security.md) · [数据存储](data-storage.md)

beta.6 新增 `/admin/audit`，仅已完成初始改密的管理员可访问。可按操作者、操作类型、结果和时间区间筛选，并逐页查看。

## 记录范围

- 登录、退出和修改密码，包括失败尝试。
- 用户创建、修改和删除。
- Provider 创建、修改、删除、批量更改和模型同步。
- 运行 / 监控配置更改、配置导入导出、检测请求、通知测试与重试。
- 手动备份和校验、模型清单批准、事件接手、指标凭据创建 / 轮换 / 撤销。
- 更新检查、更新提交、提交结果确认和历史 / 用量导出。

普通状态读取、SSE、列表轮询、健康检查和审计读取不产生记录。后台自动调度和自动通知不是管理员请求，其结果仍在任务、通知及监控运行记录中查看。

每条记录只包含服务器生成的时间、事件 ID、已验证的用户 ID / 用户名 / 角色、白名单操作名、HTTP 状态和结果。失败登录不保存提交的用户名，未认证请求的操作者显示为“未认证”。已经验证的普通用户或管理员遭遇权限 / CSRF 拒绝时仍可记录其身份。

**不保存**请求路径、查询字符串、请求或响应正文、地址、请求头、密码、会话值、CSRF、API Key、指标凭据或原始错误。用户名中的控制字符被移除，长度受限。不会为了记录参数而重新读取请求正文，也不提供参数或密钥的历史版本。

## 结果含义

| `result` | 含义 |
| --- | --- |
| `success` | HTTP 请求正常返回，不代表第三方已完成最终处理 |
| `accepted` | HTTP 202，异步任务已受理，最终结果须查看对应任务 |
| `denied` | HTTP 401 / 403 / 429，身份、权限、CSRF 或限流拒绝 |
| `error` | 其他 HTTP 4xx / 5xx |

通知平台可能在 HTTP 200 内报告拒绝，因此通知是否送达仍以通知记录为准。更新“已受理”不等于安装成功。操作审计不是任务进度或上游账单。

## 保留与可靠性

SQLite `admin_audit` 最多保留最近 10,000 条及 90 天内记录，写入时清理，查询也隐藏过期记录。无删除审计的管理 API；删除用户不会级联删除审计身份快照。记录跟随数据库备份，不包含在配置 JSON 导出中。

HTTP 处理完成后使用独立的 2 秒上下文尝试写入；浏览器取消不会主动取消这次写入。审计与业务修改不是同一事务，写入失败会记服务端错误，不回滚已完成的操作。进程强杀、数据库不可写、长时间数据库占用或磁盘故障可能导致记录缺失；审计失败不代表操作未执行。

这不是防篡改或合规审计系统。拥有数据库 / 服务账户权限的人可以修改文件；大量请求可能挤出更早记录。需要长期、独立留存时应另行保护和归档数据库，并配置反向代理访问日志与限流。

## API

`GET /api/admin/audit` 需要管理员会话，查询参数：

| 参数 | 说明 |
| --- | --- |
| `actor` | 已验证用户名的精确匹配 |
| `action` | 白名单操作名，如 `providers.update`、`auth.login`、`updates.start` |
| `result` | 空 / `success` / `accepted` / `denied` / `error` |
| `start` / `end` | 可选带时区 RFC3339 时间，含开始、不含结束 |
| `limit` | 1–100，默认 50 |
| `before` | 上一页的 `next_before`；首屏省略或为 0 |

响应包含 `items`、`has_more`、`next_before` 和 `actions`（支持的操作名）。按事件 ID 倒序，改变筛选条件必须清空游标。界面按浏览器时区输入并转换为 UTC 请求；参数不合法返回 400，未登录 401，普通用户 403。
