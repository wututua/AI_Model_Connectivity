# 检测与运维功能

[项目首页](../README.md) · [文档索引](README.md) · [配置参考](configuration.md) · [HTTP API](api.md)

本文描述当前分支的功能；已发布版本请以对应 Release 为准。

## 探测协议与参数

Provider 编辑页的「探测配置」提供轻量 Chat、推理参数、Responses 和 Chat 流式预设。预设只填入参数，不检测或推断模型能力；上游不支持时需按其要求调整。

| `probe` 字段 | 默认 / 范围 | 行为 |
| --- | --- | --- |
| `protocol` | 空值或 `chat`、`responses` | 相对 Base URL 请求 `/chat/completions` 或 `/responses` |
| `stream` | `false` | 使用相应协议的 SSE 流式响应 |
| `max_tokens` | `0` 等效 16，最高 131072 | 输出上限；Responses 映射为 `max_output_tokens` |
| `token_limit_field` | 空值等效 `max_tokens` | Chat 可选 `max_tokens` / `max_completion_tokens` |
| `omit_temperature` / `temperature` | `false` / `0`，温度范围 0–2 | 可完全省略 temperature |
| `timeout_seconds` | `0` 使用全局值，最高 86400 秒 | 包括请求到流结束的完整耗时 |
| `prompt` / `system_prompt` | 空值使用全局启动默认，最多 4096 字符 | 自定义文本提示词 |
| `omit_system_prompt` | `false` | 为 true 时不发送系统消息或 instructions |

Responses 请求使用 `store=false`。仅有效文本完成才判成功；空文本、仅思考标签、截断、错误事件或缺少流结束标记均判失败。Chat 流请求包含 `stream_options.include_usage=true`，上游须兼容该参数；否则选择非流式探测。流中的 Token 用量仅按实际上报记录，不推算缺失用量。

模型详情分别展示首段有效文本 `first_token_ms` 和完整响应 `latency_ms`；首段有效文本不包括仅有角色或思考内容的片段。旧历史无首段测量时为 0，不代表真实首段延迟为零。

## 模型重测与进度

Provider 的模型检测入口支持勾选一个或多个模型，也可仅重测该 Provider 的失败模型；概览可以重测整个最新报告中的失败模型。每次最多 1000 个，`failed_only` 仅包含 `status=error`，不包含慢、未知或发现失败。

- 弹窗按后端当前检测范围列出模型，应用跳过规则和每 Provider 模型数上限；已配置但尚未检测的模型仍可选择。只接受当前已启用、未暂停、未排除且属于已配置/已知范围的模型；运行前再次核对当前配置。
- 自动发现失败且没有具体模型结果时，需重测整个 Provider。
- 仅重测实际选中的模型，不再次自动发现，不写入其他模型的历史；未重测模型保留原 `checked_at`。
- 模型级任务不刷新 Provider 的完整检测时间，也不清除 Provider 的发现错误。
- 检测进度独立于正式报告，显示阶段、总数、完成数、活动模型和耗时；最终提交前不发布部分结果。
- 只有完整全量任务参与自动告警和防抖；Provider / 模型级重测用于排障，不作为整个告警范围的恢复证据。

## 分组与批量管理

Provider 可保存一个 `group`（最多 128 字符）及最多 20 个 `tags`（每个 1–64 字符）。管理页支持搜索、分组/标签筛选、选择条目后批量启用、停用、暂停、恢复检测或设置分组；批量操作整次校验、原子保存，ID 无效时不会部分更新。

成功删除 Provider 时立即移除其选中状态；刷新列表也会清理已不存在的 ID。搜索和分组筛选只影响显示，不清除仍然存在的选中项。

复制配置会带上模型和探测参数，但不复制 API Key；副本默认停用，必须填写新 ID 并保存。修改分组或标签不使已有检测结果失效；修改探测参数会生成新的连接版本，当前结果回到未检测，历史仍保留。

## 请求预算

在「系统设置 → 历史与调度」设置：

- `daily_request_limit`：每天由本服务发出的上游模型和模型发现请求上限，0 不限制，最高 10000000。
- `discovery_model_limit`：自动发现原始模型数的确认阈值，0 不限制，最高 100000。超过阈值时不探测该 Provider，需在编辑页明确选择并保存模型。这一检查在跳过规则和模型数量裁剪之前执行。

预算按 UTC 日界重置，持久保存已预留的请求次数；发出前在事务内预留，失败、超时和进程中断不退回。编辑页的模型同步也计数；通知请求不计数。升级前的请求不会回填预算计数，预算从新功能启用的实际预留开始。

达到上限后，新的检测/发现请求被拒绝；调度器继续运行但跳过检测，UTC 次日或提高限额后恢复后续调度。进行中的已预留请求可以结束。若一个任务中途耗尽预算，任务以错误结束，不覆盖最新报告，但已确认用量仍保存。

**请求上限不是费用上限。** 每次请求的输入、输出、推理计费和未知用量无法据此严格封顶；模型自动发现也不保证返回列表稳定。概览输出预算参考按所设上限和平均周期计算，不是账单。

## 告警防抖与维护

「系统设置 → 通知」可设置 `notify_failure_threshold`、`notify_recovery_threshold`（0/1 均等效一次，最高 100 次），按聚合状态连续观测，慢状态也使用异常阈值。未知或不再满足连续条件会清空候选计数，切换过滤范围、Provider 模型清单、跳过规则、模型数量限制、连接版本或防抖配置后重新累计。计数跨重启保留。

完整检测结束后会对比任务开始时与发送通知前的范围。若范围已变化，该任务仍保存实际用量和历史、按当前配置更新状态页，但不发送异常或恢复通知，并清空候选计数；新范围须由后续完整检测重新累计。仅修改分组或标签不影响此判断。

通知停用或渠道配置不完整时，完整检测会清空尚未达到阈值的候选计数，不修改上次已通知状态和冷却时间；重新启用后从新的检测结果开始累计。

`maintenance_start` / `maintenance_end` 为一对带时区的 RFC3339 时间；两者均为空表示关闭。维护区间含开始、不含结束，只静默正式通知，不停止检测，不把静默期判成恢复。测试通知和手动重试仍可发送。界面按浏览器时区输入并转换为 UTC 保存。

测试、发送历史与重试行为见[通知记录](api.md#通知记录)。HTTP 成功只表示平台接受，不保证用户实际收到。

## 数据导出

「运维工具 → 数据导出」支持检测历史和每日用量，按 UTC 起止日期（含结束日）、Provider ID、模型筛选，单次最多 366 天、10000 条；超限必须缩小范围，不会静默截断。历史受启用开关和历史保留策略限制，用量受独立 365 天聚合保留策略限制。

CSV 包含 UTF-8 BOM，按 CSV 规则转义；可能被电子表格解释为公式的字符串增加前导单引号。默认不导出原始错误和响应正文。

脱敏诊断 JSON 只包含运行平台、Go 版本、Provider 数量、请求预算和选定安全开关，不包含 Provider 名称、ID、地址、提示词、凭据、用户或原始任务错误。仍应在分享前检查文件，导出不是数据库备份。

## 指标凭据

「运维工具 → 指标凭据」最多创建 20 个独立凭据。创建和轮换时完整值仅返回一次，不写入浏览器持久存储；数据库仅保存 256 位随机凭据的 SHA-256 哈希。

凭据仅接受在 `GET /metrics` 的 `Authorization: Bearer <凭据>` 请求头中；不能访问管理、状态或导出 API，不能替代会话。轮换立即撤销旧值，删除立即撤销当前值；已下载的指标不能撤回。凭据为服务级，不会随某个管理员退出或改密自动撤销，应在不再使用时显式删除。

旧版管理 Bearer Token 仍然无效，普通用户的会话抓取方式也继续受支持。自动采集配置示例见[Prometheus 指标](operations.md#prometheus-指标)。
