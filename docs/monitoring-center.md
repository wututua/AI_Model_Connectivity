# 监控中心

[文档索引](README.md) · [检测与运维](monitoring-features.md) · [备份恢复](operations.md#备份与恢复)

本文描述当前开发分支；监控中心自 beta.5 提供，beta.6 增加历史筛选分页。管理入口为 `/admin/monitoring`，仅管理员可访问。能力探测参数仍位于 Provider 编辑页。

## 诊断

保存最近探测记录中的 DNS、TCP 连接、TLS 握手、HTTP 首字节、首段有效文本和完整响应耗时，附带 HTTP 状态、有限长度的请求 ID 和 Retry-After。

- 网络阶段未发生或未测到时显示 `-`；连接复用不等于零耗时的新连接。
- DNS/连接可发生多次，展示累积值；它们不是可直接相加的服务端耗时分解。
- HTTP 首字节与首段模型文本不同，流式响应中角色或思考片段不算有效文本。
- 不记录任意响应头、请求头和完整响应；请求 ID 中的当前 Provider 密钥会被替换。
- 诊断历史依赖历史记录开关与原有保留策略。面板可按 Provider、模型、结果、能力、错误类型和时间筛选，每页 25 / 50 / 100 条；公开状态接口及 SSE 不暴露诊断元数据。

## 模型清单

自动发现第一次完整成功返回时建立基线。后续新增模型进入待批准列表，管理员确认后参加下一轮自动检测；不立即发起请求。已批准模型重新出现时可继续检测。

发现失败、超出响应大小上限、超过模型发现数量阈值或检测中连接配置变更，不作为新清单写入。手动配置模型清单不受此批准流程限制。切换 Provider 连接版本会建立新基线，原版本清单不能继续批准。

批准需要同时提交 Provider ID、连接版本和清单观测时间。面板有待批准列表及最近 100 条变更；数据库保留最近 1000 条变更。新增批准仍受每日请求预算、模型排除及数量上限限制。

## 备份

- 自动备份默认关闭，周期范围 1–8760 小时；保留数量 1–100，默认 7。
- 保存位置为 `DATA_DIR/backups`。使用 SQLite `VACUUM INTO` 生成一致性快照，完成后同步文件、执行 `quick_check` 并保存 SHA-256。
- 手动与自动备份互斥。仅新备份成功且登记后才按保留数量删除旧备份；拒绝路径穿越、目录链接和非普通备份文件。
- 校验会重新检查数据库结构和哈希，不恢复数据。浏览器断开可能取消手动备份，重新操作前先刷新列表。
- 定时工作每分钟检查一次，失败后至少等待 15 分钟才自动重试。备份失败在运行记录中显示，可选通知推送。
- 备份包含账号、会话、Provider 与通知凭据，必须按敏感数据保管；没有网页下载或网页覆盖恢复入口。
- 在线快照可能占用较长时间及额外磁盘空间，SQLite 的单连接会让其他数据库操作等待。完整恢复步骤仍见运维指南，恢复演练不能由哈希校验代替。

## 独立告警

旧全局通知继续有效。新增最多 50 条规则，每条规则独立设置渠道、Provider / 模型范围、失败阈值、恢复阈值和冷却；同一范围发往多个渠道时建立多条规则。

规则默认停用，凭据不会由读取接口返回。编辑时留空保留相同规则、相同平台的原凭据；删除规则后凭据一同删除。修改规则会更新其内部代次，避免旧状态沿用。

- 全量任务可评估全部规则；Provider 完整任务只评估明确绑定该 Provider 的规则。
- 选中模型和失败项重测不触发规则告警，不被当作完整范围恢复证据。
- 告警防抖、维护及范围变更保护沿用现有逻辑。事件接手与人工测试不会改变告警状态。
- 测试和重试都写入通知记录；重试使用原规则当前保存的渠道，规则已删除或停用则拒绝，不回退到全局渠道。
- 规则可订阅模型清单变更。备份失败和月度预算属于服务整体，只能由未限定 Provider / 模型的规则订阅。
- 运维提醒每分钟处理，单轮最多实际发送 10 条。清单及备份事件只发送最近 24 小时记录；每个规则每月仅一次预算越限提醒。
- 同一运维事件先持久预留再发送，失败间隔至少 15 分钟、最多自动尝试 3 次；中断或结果落库未确认时不自动重放，可在通知记录核实后手动重试。

## 事件

每个 Provider / 模型有独立的未恢复事件，模型发现失败单独记录。连续异常更新同一事件；正常结果将该模型对应事件恢复，未知结果不会恢复。

人工接手只记录接手时间与备注，不把模型标为正常。新连接版本的观测会将旧版本未恢复事件标为“配置已变更”，不伪造旧接口恢复。

面板支持 Provider、模型、状态、发现时间筛选，并可单独查看模型发现事件；按 ID 倒序翻页，可选择「待恢复」查看未结束事件。数据库保留未恢复事件和最近 2000 条内的已结束事件。停用 / 暂停 Provider 不会被当作发现恢复证据。时间是检测观测边界，不代表精确故障发生时间或连续 uptime。事件与通知分别记录，不是一条事件对应一次通知。

## Provider 调度

没有设置独立周期时，沿用全局随机区间的完整检测。任一 Provider 设置正数周期后启用独立调度：

- 正数周期覆盖该 Provider 的全局周期；0 表示继承。
- 未单独配置的 Provider 按全局区间平均值调度，取整分钟，最短 1 分钟；全局周期关闭时这些 Provider 不自动检测。
- 首次启用、周期变更、连接版本变更会从当前时间重新安排；已保存的相同周期和版本跨重启保留到期时间。
- 工作每分钟检查到期项，长任务、单实例任务互斥及预算不足可能延迟执行，不承诺整点或精确分钟执行。
- 同一时刻仍只运行一个检测任务，所有请求继续使用持久请求预算。
- 独立调度按 Provider 产生完整观测，因此应配置 Provider 范围的独立告警。旧全局通知及跨 Provider 规则仍需要手动或启动全量检测。
- 慢响应阈值 0 继承全局阈值。Provider 维护窗口使用 UTC 输入，只静默绑定此 Provider 的规则，不停止探测；全局维护仍按原设置生效。

## 能力探测

`probe` 新增以下字段：

| 字段 | 行为 |
| --- | --- |
| `capability` | 空 / `text`、`tools`、`embedding` |
| `assert_contains` | 文本响应必须包含指定子串，区分大小写 |
| `assert_json` | 文本必须是合法 JSON 对象，不接受数组或 null |
| `assert_json_keys` | 逗号分隔的必需顶层字段名，启用时也要求 JSON 对象 |

工具检测使用非流式 Chat Completions，要求返回指定函数名与 `{"ok":true}` 参数，只校验结构，永不执行外部工具。Embedding 检测调用 `/embeddings`，要求非空数值向量。两者不支持 Responses、原生 Anthropic / Gemini 或流式配置。

诊断分别记录 `passed`、`assertion_failed` 和 `request_failed`。断言不符只说明本次能力校验失败，不能据此断定模型质量或认定整个服务离线；仍按失败探测参与所配置范围的状态与告警。可选能力不会额外自动执行第二个请求。

## 费用

按 Provider / 模型设置每百万输入、输出 Token 的 USD 单价。每个结果入库时使用当时有效价格，金额随每日汇总持久保存，后续改价不改写旧金额。

缺少价格或必需用量字段时计入“未知费用请求”，不计作免费。历史用量不会按新价格追溯填账，费用功能从升级后新记录开始；保留 365 天每日金额，面板显示当前 UTC 月。

该估算不覆盖缓存、分层、推理、批量及其他特殊计价，不处理汇率。月度预算为提醒而非强制停机限额；严格请求上限仍使用原有每日请求预算，最终费用以上游账单为准。

## API 与存储

所有接口要求管理员会话，写操作要求同源及 CSRF。

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| GET | `/api/admin/monitoring` | 安全配置、诊断、清单、事件、备份、调度与费用 |
| GET | `/api/admin/monitoring/diagnostics` | 诊断历史筛选及游标分页 |
| GET | `/api/admin/monitoring/incidents` | 事件历史筛选及游标分页 |
| PUT | `/api/admin/monitoring/settings` | 保存完整监控配置，必须携带读取到的 `version`；过期版本返回 409 |
| POST | `/api/admin/monitoring/backup` | 手动备份 |
| POST | `/api/admin/monitoring/verify` | `{ "name": "已登记的备份文件名" }` |
| POST | `/api/admin/monitoring/approve` | `{ "provider_id": "...", "revision": "...", "updated_at": "..." }` |
| POST | `/api/admin/monitoring/ack` | `{ "id": 1, "note": "..." }` |
| POST | `/api/admin/monitoring/test-rule` | `{ "id": "规则 ID" }` |

监控配置在 SQLite `runtime_config` 的 `monitoring` 项中保存，不读取启动环境变量。原配置导入导出仍仅覆盖原运行设置和 Provider，不包含新监控配置；完整迁移应使用数据库备份。新表包括 `model_catalog`、`catalog_events`、`backups`、`incidents`、`provider_schedule`、`cost_daily`、`monitoring_events` 和 `monitoring_notices`，均在启动时创建。

两个历史接口接受 `provider_id` / `model` 精确匹配、`status`、带时区 RFC3339 的 `start` / `end`（含开始、不含结束）、`limit`（1–100，默认 50）和 `before`（上一页 `next_before`）。诊断额外支持 `capability` 和 `error_type`；事件支持 `scope=models` / `discovery`，后者不能同时指定模型。

返回 `{"items":[],"has_more":false,"next_before":0}`。历史按 ID 倒序；改变筛选条件须清空游标。新写入记录不会挤动后续页，但这不是跨请求的数据库快照，已恢复或被清理的记录可能改变筛选结果。旧聚合接口保留最近 100 条诊断与 200 条事件，兼容既有客户端。

管理员请求的身份及结果在独立的[操作审计](audit.md)中查看，不与备份运行记录混为一谈。
